# Step 3 — JPA Entities & Relationships

> **Prompt**: "Explain all the JPA entity classes in the entity package. What do they represent, how are they related to each other, and how do they map to the database tables?"

---

## What JPA Entities Are

A JPA entity is a Java class annotated with `@Entity`. Hibernate (the JPA implementation Spring Boot uses) maps each entity class to a DB table, and each field to a column. When you call `repository.findById(1L)`, Hibernate runs `SELECT * FROM table WHERE id = 1` and turns the result row into a Java object.

---

## Core Annotations Used in This Project

| Annotation | Meaning |
|---|---|
| `@Entity` | Marks this class as a database-mapped object |
| `@Table(name="x")` | Maps to table named `x` (if different from class name) |
| `@Id` | This field is the primary key |
| `@GeneratedValue(strategy = GenerationType.IDENTITY)` | DB auto-increments the ID (uses `GENERATED BY DEFAULT AS IDENTITY`) |
| `@Column(name="x")` | Maps to column `x` (when field name differs from column name) |
| `@Column(columnDefinition = "TEXT")` | Forces the column type to TEXT (for long strings) |
| `@OneToMany` | "This entity has a list of another entity" |
| `@ManyToOne` | "Many of this entity belong to one of that entity" |
| `@JoinColumn(name="fk_col")` | The foreign key column name |
| `@ElementCollection` | Maps a `List<String>` to a separate simple table |

## Entity 1 — `Profile.java` → table `profile`

```java
@Entity @Table(name = "profile")
@Getter @Setter @NoArgsConstructor @AllArgsConstructor @Builder
public class Profile {
    @Id
    private Long id;              // ← Note: NO @GeneratedValue — ID is always set to 1 manually

    private String name;
    private String headline;

    @Column(name = "sub_headline", columnDefinition = "TEXT")
    private String subHeadline;   // ← field name differs from column name

    @Column(name = "resume_url")
    private String resumeUrl;

    private String email;

    @Column(name = "linkedin_url") private String linkedinUrl;
    @Column(name = "github_url")   private String githubUrl;
    @Column(name = "youtube_url")  private String youtubeUrl;
    @Column(name = "instagram_url") private String instagramUrl;
    @Column(name = "facebook_url") private String facebookUrl;
}
```

**Key insight**: There's no `@GeneratedValue` on `id`. The admin controller manually sets `profile.setId(1L)` before saving — this is a **singleton entity**. The database will always have exactly one row.

## Entity 2 — `User.java` → table `users`

```java
@Entity @Table(name = "users")
public class User implements UserDetails {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String email;
    private String password;   // BCrypt hashed
    private String role;       // "ROLE_ADMIN"

    @Override
    public Collection<? extends GrantedAuthority> getAuthorities() {
        return List.of(new SimpleGrantedAuthority(role));
    }

    @Override
    public String getUsername() { return email; }  // Spring Security uses email as username
}
```

**Key insight**: `User` implements Spring Security's `UserDetails` interface. This is how Spring Security knows how to load the user from the database for authentication. `getUsername()` returns the email, and `getAuthorities()` returns `[ROLE_ADMIN]`.

## Entity 3 — `SkillCategory.java` + `Skill.java` → `skill_categories` + `skills`

```java
@Entity @Table(name = "skill_categories")
public class SkillCategory {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String categoryName;   // e.g. "Frontend & UI"

    @OneToMany(mappedBy = "category", cascade = CascadeType.ALL)
    private List<Skill> skills;    // ← one category has many skills
}
```

```java
@Entity @Table(name = "skills")
public class Skill {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String skillName;   // e.g. "React"
    private String iconName;    // e.g. "FaReact"

    @ManyToOne
    @JoinColumn(name = "category_id")
    private SkillCategory category;  // ← many skills belong to one category
}
```

**Relationship**: `SkillCategory` →(1 to many)→ `Skill`

- `@OneToMany(mappedBy = "category")` — the `SkillCategory` side says "the `category` field in `Skill` owns this relationship"
- `@ManyToOne @JoinColumn(name="category_id")` — the `Skill` side holds the actual foreign key column `category_id`
- `cascade = CascadeType.ALL` — if you delete a `SkillCategory`, all its `Skill` rows are also deleted

## Entity 4 — `Project.java` + `ProjectLink.java` → `projects` + `project_links`

```java
@Entity @Table(name = "projects")
public class Project {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String title;
    private String thumbnailPath;

    @Column(columnDefinition = "TEXT")
    private String description;

    @ElementCollection
    @CollectionTable(name = "project_tech_stack", joinColumns = @JoinColumn(name = "project_id"))
    @Column(name = "tech_name")
    private List<String> techStack;   // ← stored in a separate table, not a column

    @OneToMany(cascade = CascadeType.ALL, orphanRemoval = true)
    @JoinColumn(name = "project_id")
    private List<ProjectLink> ctaLinks;
}
```

**Two special patterns here:**

1. **`@ElementCollection`** — `techStack` is a `List<String>`. JPA maps this to a separate table called `project_tech_stack` with a `project_id` foreign key and `tech_name` column. No separate entity class is needed.

2. **`orphanRemoval = true`** — if you remove a `ProjectLink` from the `ctaLinks` list and save, that `project_links` row is automatically deleted from the DB.

## Entity 5 — `ContactMessage.java` → table `contact_messages`

```java
@Entity @Table(name = "contact_messages")
@Builder
public class ContactMessage {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private String name, email, subject, message;
    private String ipAddress;
    private LocalDateTime createdAt;
}
```

- `@Builder` → allows `ContactMessage.builder().name("...").email("...").build()` — used in `ContactServiceImpl`
- No relationship to any other entity — standalone audit log

## Lombok Annotations Quick Reference

| Annotation | What it generates |
|---|---|
| `@Getter` | `getName()`, `getEmail()`, etc. for all fields |
| `@Setter` | `setName()`, `setEmail()`, etc. for all fields |
| `@NoArgsConstructor` | `public Profile() {}` |
| `@AllArgsConstructor` | Constructor with all fields as params |
| `@Builder` | `Profile.builder().name("...").build()` pattern |
| `@Data` | `@Getter + @Setter + @ToString + @EqualsAndHashCode` |
| `@RequiredArgsConstructor` | Constructor for all `final` fields (used for DI) |
