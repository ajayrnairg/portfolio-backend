# Step 2 — Database Schema & Flyway Migrations

> **Prompt**: "Walk me through the Flyway migration files (V1 through V8) in order. What tables are created, what changed between versions, and what does the final database schema look like?"

---

## How Flyway Works

When the app starts, Flyway scans `src/main/resources/db/migration/` and runs any SQL scripts that haven't been applied yet. It tracks applied scripts in its own internal `flyway_schema_history` table.

**Rules:**
- Files must be named `V{number}__{description}.sql`
- They run in **version number order**, exactly **once**
- Once applied, **never edit them** — add a new Vn file instead
- `baseline-on-migrate: true` in `application.yml` allows Flyway to work on a DB that already has tables

## V1 — `V1__Initial_Setup.sql` — The profile table

```sql
CREATE TABLE profile (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    headline VARCHAR(255) NOT NULL,
    sub_headline TEXT,
    resume_url VARCHAR(500),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

INSERT INTO profile (name, headline, sub_headline, resume_url)
VALUES ('Ajay Nair', 'Transforming Ideas Into Scalable Architecture', '...', 'https://...');
```

- Creates the `profile` table — this is the hero/landing section
- Seeds the first (and only) row — this is a **singleton** table; there's always exactly 1 row with `id = 1`
- `GENERATED BY DEFAULT AS IDENTITY` = PostgreSQL's auto-increment

## V2 — `V2__Add_Download_Tracking.sql` — Resume download logs

```sql
CREATE TABLE resume_download_log (

    ip_address VARCHAR(50),
    downloaded_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

- Added so the app can track who downloaded the resume (by IP)

## V5 — `V5__About_Section.sql` — The full about section

This is the largest migration. It creates 6 tables:

```sql
CREATE TABLE about_section (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    title VARCHAR(255),
    description TEXT,
    years_experience VARCHAR(10),    -- e.g. "2.5 +"
    projects_completed VARCHAR(10),  -- e.g. "10 +"
    tech_debt_reduced VARCHAR(10)    -- e.g. "40 %"
);

CREATE TABLE skill_categories (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    category_name VARCHAR(100) NOT NULL  -- e.g. "Frontend & UI"
);

CREATE TABLE skills (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    category_id BIGINT REFERENCES skill_categories(id),  -- FK!
    skill_name VARCHAR(100) NOT NULL,   -- e.g. "React"
    icon_name VARCHAR(100) NOT NULL     -- e.g. "FaReact"
);

CREATE TABLE awards (id, title, stage, description);
CREATE TABLE experience (id, title, stage, description);
CREATE TABLE certifications (id, title, stage, description);
```

Seeds real data:
- 3 skill categories: Frontend & UI, Backend & APIs, Data & Cloud
- 9 skills spread across them
- Ajay's work experience at ISS-STOXX
- 2 awards (Microsoft AI Grant, Hackathon winner)
- 2 certifications (B.E. Mumbai, ML Coursera)

## V6 — `V6__Contact_Section.sql` — Contact messages

```sql
CREATE TABLE contact_messages (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(255),
    email VARCHAR(255),
    subject VARCHAR(255),
    message TEXT,
    ip_address VARCHAR(50),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

Every contact form submission gets saved here. The admin can view and bulk-delete them via `AdminController`.

---

## V7 — `V7__Admin_User.sql` — Admin login

```sql
CREATE TABLE users (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    email VARCHAR(255) UNIQUE NOT NULL,
    password VARCHAR(255) NOT NULL,   -- BCrypt hash
    role VARCHAR(50) NOT NULL
);

INSERT INTO users (email, password, role)
VALUES ('spamvinup@gmail.com', '$2a$10$...hashed...', 'ROLE_ADMIN');
```

- The password stored is a **BCrypt hash** of `admin123` — never the plain text
- `role = 'ROLE_ADMIN'` — Spring Security requires roles to start with `ROLE_`
- Only one admin user; you'd add another row to create more

## V8 — `V8__Add_Contact_Info_to_Profile.sql` — Social links

```sql
ALTER TABLE profile
    ADD COLUMN email VARCHAR(255),
    ADD COLUMN linkedin_url VARCHAR(255),
    ADD COLUMN github_url VARCHAR(255),
    ADD COLUMN youtube_url VARCHAR(255),
    ADD COLUMN instagram_url VARCHAR(255),
    ADD COLUMN facebook_url VARCHAR(255);
```

This is a perfect example of **why Flyway exists**: rather than editing V1 (which already ran), a new V8 migration adds columns to the existing table. Zero data loss.

## Key Relationships

| From | To | Type | Via |
|---|---|---|---|
| `skills` | `skill_categories` | Many→One | `category_id` FK |
| `project_tech_stack` | `projects` | Many→One | `project_id` FK |
| `project_links` | `projects` | Many→One | `project_id` FK |
| `resume_download_log` | (standalone) | — | no FK to profile |
| `contact_messages` | (standalone) | — | no FK |
| `experience`, `awards`, `certifications` | (standalone lists) | — | no FK |
